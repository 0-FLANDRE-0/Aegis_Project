# 실행 SHA와 증거 재사용

원시 시험 결과의 실행 HTML SHA를 최종 HTML SHA로 덮어쓰지 않는다. `evidence/execution-manifest.json`은 최종 수집 시 실행 파일별 SHA를 열거한다.

## 960회 G7

최초 측정 HTML SHA: `3e431e9909ef040293a2906f2013fc73ae9de4e21cde6e573e2ed04c7645d42f`.

그 이후 변경은 다음뿐이다.

- PiP에서 잘리던 9km 라벨의 read-only 배치.
- 하푼 물리 객체의 SI 좌표/속도와 기존 종료·사후 로그 연결.
- 자율 함포의 수동 인계 예약과 기존 급탄 주기 후 사격. 수동 인계가 없으면 예약 집합은 비어 있다.
- 물리 객체 위상: 항공기·하푼·NPC SAM/RAM은 포탄보다 먼저 이동하므로 현재 속도로 선형 swept 구간의 시작을 환산한다. ASM·자함 SAM/RAM·헬기는 포탄 이후에 이동하므로 기존 시작점 그대로다. 엔티티를 수정하지 않는다.

G7 조건에는 항공기, 하푼, NPC 함정과 운용자 사격 명령이 없다. 따라서 위 세 조건부 효과/명령 변경의 활성 경로가 없으며 Kh-35U 물리 근접·탄도·자율 선정 계산은 같다. `evidence/engine-equivalence.json`은 전체 역변환 문맥과 적용 조건을 보존한다. `verify_engine_equivalence.py`가 최종 HTML에서 이를 역변환해 최초 측정 HTML의 SHA를 정확히 재구성한다. `verify_effect_equivalence.py`는 DDG/CG × 정면/측면 × 1/4발 × ON/OFF 16쌍에서 실제 full-world 결과와 전투 RNG, 배제 조건을 추가 확인한다.

## 기존 회귀

기존 검사는 명시적으로 자동 대공 OFF이며 새 MFF를 발사하지 않는다. 물리 어댑터는 MFF 신관에만 연결돼 있다. 자동 인계 예약은 없고 native 비행 지문 281개와 ENV_D 블록은 byte 동일이다. 개별 시험이 어느 중간 후보에서 실행됐는지 원래 SHA를 유지한 채 이 조건으로 재사용한다. 최종 후보의 신규 native·물리·UI·인계 시험과 G7의 최종 후보 동등성 검사는 별도로 확인한다. 기준을 바꿔 결과가 달라진 CG 상태 비교는 재사용 명목으로 통과 처리하지 않는다.

## 렌더/질량 원인 증거

Mod4 실제 포구 검사는 렌더·포구 생성 코드가 고정된 후보에서 실행했다. 이후 위 변경에는 렌더 생성기·hardpoint·포구 변환이 없다. 약 6mm 오차와 실제 62구경 faceted 메시 캡처를 그대로 보존한다. 질량 노드 원인 검사는 제품의 질량·침수 코드를 바꾸지 않는 read-only 복사 계산이다.
