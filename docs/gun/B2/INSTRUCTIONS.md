## 1. 현재 코드에서 확인된 사실 (리뷰어 분석, Phase 0에서 검증할 것)

1. **산포 0**: `spawnMainGunProjectileWip13B3`가 조준 방향과 `ammo.muzzleVelocityMps`를 그대로 쓴다. 발마다 각도 편차도 포구속도 편차도 없다. 수상 사격도 같은 함수를 지난다.
2. **사격해 노후화**:
   - 사격해는 `solutionRefreshIntervalS`=1 s마다 갱신된다.
   - 발사는 `maxReleaseSolutionAgeS`=1.2 s까지 허용된다.
   - 발사 순간에 사격해를 다시 전파하지 않는다. 몸체 각만 매 틱 다시 투영한다(WIP13B15).
   - 280 m/s급 ASM이면 1 s 사이에 진행 방향으로 ~280 m 움직인다.
3. **대공에 수상용 포인팅 창 사용**: `requestFire`가 공중 사격해에도 `wip13b6GunPointingAssessment`를 쓴다.
   - 관측 크기가 없으므로 수상 fallback 창이 쓰인다: 측방 20 m, 상 7.5 m, 하 5.5 m, `releaseAimMargin01` .78.
4. **신관이 이상적이다**: `gunB1ShellEvent`의 근접 판정은 물리 객체까지의 swept CPA가 25 m 이하이면 **정확히 CPA 순간**에 터진다. 탐지 패턴, 탐지확률, 처리 지연이 없다.
   - 참고로 SM-2 신관(WIP99 Stage 2)에는 TDD 빔 패턴, 탐지확률, 처리 지연, 해면 클러터가 들어 있다.
5. **파편 Pk가 띠 기하를 확인하지 않는다**: `gunB1FragmentationPk`는 "파편 수 ÷ 띠 면적" 밀도 모델이다. 표적이 실제로 파편 띠 안에 있는지 판정하지 않는다.
   - 55° 띠는 밀도를 희석하는 역할만 한다.
   - **따라서 띠만 좁히면 Pk가 오히려 오른다.**
6. **90° 이상**: GUN_B1 G7 로그 기준이다.
   - 90°의 근접 폭발 사거리 중앙값은 ~3.0 km, 0°는 ~5.5 km다(CG ×1).
   - 90°에서는 ET 백업 폭발이 시드와 관계없이 ~5.12 km에 몰린다.
   - 롤은 원인이 아니다. 함 자세에는 침수 경사·트림만 있고 파도 롤이 없다.
   - 리뷰어의 1순위 가설은 2번(노후화)이다. 90°에서는 자함 이동이 사격선에 수직이어서 "함속 × 해 나이"가 그대로 측방 오차가 되고, 이동하는 함을 리드하는 ASM 경로에도 횡 성분이 생긴다.
   - 그 밖의 후보는 첫 발의 90° 선회, 3번 창 크기, 표적 기동이다.

## 2. Phase 0: 진단 (수치 변경 금지)

**발별 진단 로그** (진단 하네스 전용, 게임 로직은 바꾸지 않는다)
- 발사 정보: 발사 step, 사격해 `computedStep`, 해 나이(s), 마운트 몸체 방위.
- 첫 발 여부와 선회 소요 시간.
- 원점 비교: 사격해 원점과 실제 발사 원점(trunnion)의 차이 벡터, 그때 자함 속도.
- 포인팅: 발사 시점 `crossMissM`, `verticalMissM`, `limitM`.
- 트랙 오차: 발사 시점 트랙 상태와 truth의 위치·속도 오차. truth는 진단 기록에만 쓰고 사격통제 경로에서는 읽지 않는다.
- 표적 기동: 탄 비행 중 표적 truth의 평균 가속도(횡/종/수직).
- **CPA 오차 분해**: 탄-표적 최근접 시점의 상대위치를 탄 진행 방향 / 수평 측방 / 수직으로 나눈다. 표적이 25 m 밖이면 비행 중 최소거리 시점으로 분해한다.
- 결과: 폭발 사유(PROX/ET/CLUTTER), `arrivalMissM`, `pk`.

**시나리오**: GUN_B1 G7과 같다(DDG/CG × 0°/90° × 1~4발, 자동 대공 ON, 각 30회 이상).

**통제 실험** (진단 전용 플래그, 기본 OFF, 출하 빌드에서 동작에 영향이 없어야 한다)
- A: 자함 속력 0
- B: 발사 순간 사격해 재계산(§4 방식의 시험판)
- C: 직선 비행 표적(기존 테스트 표적 사용 가능 시)
- D: 대공 포인팅 허용폭을 0에 가깝게(`releaseAimMargin01` 축소)

각 실험이 0°와 90°의 `arrivalMissM` 분포, ET 비율, 오차 분해를 어떻게 바꾸는지 비교한다.

**Phase 0 산출물**
- `docs/gun/B2/PHASE0.md`와 원시 로그를 `gun-b2`에 push한다.
- 내용:
  - 원인별 기여도(오차 분해의 평균·σ)
  - 1순위 원인 결론
  - §4~§6 수정 방식 제안
  - 모든 `SIM_TUNED` 초안 값 표
- **push 후 멈추고 사용자 승인을 기다린다.**

## 3. Phase 1-A: 발별 산포 (5인치 전 사격, 수상 포함)

- `spawnMainGunProjectileWip13B3`에서 발마다 다음을 적용한다.
  - 포구속도 편차: 정규분포, σ = `mvSigmaFrac` × 공칭값
  - 각도 편차: 고각 σ `elevSigmaMrad`, 선회 σ `trainSigmaMrad`. 탄 방향에 수직인 두 축으로 적용한다.
- **RNG**:
  - 탄 serial과 `SIM_SEED_BASE`로 시드를 만드는 **전용 xorshift**를 쓴다(`gunB1ArmShell` 방식).
  - `simRandom()`을 소비하지 않는다. 다른 시스템의 RNG 흐름이 그대로 유지돼야 한다.
  - 같은 시드면 같은 결과가 나와야 한다.
- **공개 앵커와 보정**:
  - 공개된 수치는 사거리 산포 하나뿐이다. 약 18,000 yd(16,459 m) 함상 시험에서 사거리 표준편차 48 yd(43.9 m), 시험장 값은 약 60 yd(~54.9 m)다(DTIC ADA331645).
  - 하네스로 무풍·표준 대기에서 16,459 m 사격 해를 고정하고 200발 이상 쏴서 **사거리 σ가 44~55 m 안에** 들도록 `mvSigmaFrac`과 `elevSigmaMrad`를 정한다.
  - 두 값의 배분 근거를 보고서에 적는다. 포구속도 편차가 수직 산포의 주성분이라는 일반 탄도 지식을 따른다.
- **선회(편향) 산포**: 공개 자료가 없다. `SIM_TUNED`로 두고 근거를 적는다.
- **범위 밖**: 포구속도 공칭값(현 823 m/s, 공개 Mk 67 장약 808 m/s)은 이번에 바꾸지 않는다. 차이만 보고서에 기록한다.
- **진단 스위치**: 산포 전체를 끄는 내부 플래그를 둔다. 끄면 GUN_B1과 byte가 같아야 한다.

## 4. Phase 1-B: 발사 순간 사격해 정합

- Phase 0에서 노후화가 원인으로 확인되면, **발사 직전에 현재 트랙 상태와 현재 원점으로 사격해를 다시 계산**한다. 기존 seed 기반 continuation solve를 쓴다.
- 다시 계산한 해로 포인팅 판정을 다시 한다.
  - 판정을 통과하지 못하면 그 틱에는 발사하지 않는다(연속 사격은 대기, 단발은 기존 대기 로직).
  - 기존 `requestFire` 주석의 문제(클릭 후 해가 움직여 높거나 긴 탄이 빠져나감)를 반복하지 않는 것이 핵심이다. 발사되는 탄은 항상 **그 틱의 해 위에서** 나가야 한다.
- **적용 범위**:
  - 대공은 필수다.
  - 수상은 Phase 0에서 측정한 영향이 의미 있으면 함께 적용한다(PHASE0.md에서 제안, 사용자 승인).
- 성능: 발사 시에만(3 s 사이클당 1회) 계산한다. 프레임 비용을 보고한다.
- Phase 0에서 다른 원인이 1순위로 나오면 이 절 대신 그 원인의 수정안을 PHASE0.md에서 제안한다.

## 5. Phase 1-C: 대공 포인팅 창

- 공중 사격해(`airDomain`)일 때는 수상 fallback 창 대신 **대공 전용 창**을 쓴다.
  - 창 크기는 신관 탐지 반경(§6)에 연동한다. 측방·수직 대칭이며 `SIM_TUNED`.
- 수상 사격의 `wip13b6GunPointingAssessment` 동작은 바꾸지 않는다.

## 6. Phase 1-D: 근접신관 현실화

**SM 경로 보존**: `WIP99_FUZE_STAGE2_PARAMS`와 SM 신관 경로는 수정하지 않는다. 구조만 참고해 5인치 전용 파라미터 세트를 만든다.

**변경 내용** (`gunB1ShellEvent`)
- **탐지 패턴**: 탄 축 기준 극각 중심과 반폭(`SIM_TUNED`)의 전방 경사 환형 패턴. 표적이 패턴 안에 있고 탐지 거리 안에 있어야 탐지된다.
- **탐지 시점 기폭**: CPA 순간이 아니라 **처음 탐지된 시점 + 처리 지연**(`SIM_TUNED`)에 기폭한다. swept 구간 안에서 탐지 시작 시점을 찾는다.
- **탐지확률**: 통과(pass)당 1회 판정한다. RCS 의존성은 기존 `getASMRcs`/ASM_PROFILES를 쓴다. 값은 `SIM_TUNED`이고 전용 RNG를 쓴다.
- **유지**: 안전 거리, ET 백업, 해면 클러터는 그대로 둔다.
- 신관은 물리 장치이므로 world 객체를 읽는 것은 지금처럼 허용한다.

## 7. Phase 1-E: 파편 띠 기하 판정

**SM 경로 보존**: `gunB1FragmentationPk`는 5인치 전용 복사본이므로 여기서만 수정한다. `_wip88FragmentationPk`와 SM/ESSM 경로는 byte 동일해야 한다.

**변경 내용**
- **띠 안 판정 추가**: 기폭 시점의 탄 속도 + Gurney 파편 속도로 정해지는 파편 분사 방향 띠를 계산한다. 파편 비행시간 동안의 표적 상대운동을 반영해, **표적 도달 방향이 띠 안에 있을 때만** 밀도 기반 Pk를 적용한다. 띠 밖이면 Pk 0(또는 보고서에서 정한 경계 완화).
- **띠 반폭**: 현재 55°에서 원통형 탄체 측면 분사에 맞게 줄인다. 값은 `SIM_TUNED`이고 근거를 보고서에 적는다.
- **세트 적용**: 띠 축소와 띠 안 판정은 **반드시 함께** 적용한다. 하나만 넣은 중간 상태로는 출하하지 않는다.
- 결과 처리 경로(격추·손상·잔해·로그)는 GUN_B1과 같다.

## 8. Phase 1-F: 실효 사거리 측정과 링

- 하네스로 Kh-35U 해면밀착 표적을 정면과 측면에서 접근시키고, 요격 거리 구간(1 km 간격, 1~9 km)별 **단발 Pk 분포**를 측정한다.
  - 산포, 신관, 파편, 노후화 수정이 모두 적용된 상태로 측정한다.
- 보고서에 거리-단발 Pk 곡선(평균·10/90%)을 싣는다.
- **링**: 제안값은 정면 평균 단발 Pk가 0.05 아래로 떨어지는 거리다.
  - `5in` 선택 시 점선 링 라벨을 `대공 유효 Xkm (SIM)`으로 바꾼다.
  - 이 값은 PR 검토에서 사용자가 확정한다.
- `autoRangeM`(9 km)은 바꾸지 않는다. 링과 자동 교전 범위가 다르면 둘 다 표시하고, 레이아웃 방식은 보고서에서 제안한다.

## 9. 보존 조건

- 사격통제·UI·자동 선정은 표적 truth를 읽지 않는다. 신관과 파편만 물리 world를 읽는다. 진단 로그의 truth 기록은 진단 하네스에서만 한다.
- 비행 지문 281개, 사거리표 120행 byte 동일. SM/ESSM/SM-6/하푼/CIWS 결과 byte 동일.
- **B2 기능을 모두 끈 상태**(산포·재정합·대공 창·신관·파편 플래그 OFF)에서는 GUN_B1 회귀와 byte 동일해야 한다.
- **기능 ON 상태의 회귀**:
  - 수상 함포가 개입하는 회귀(MAP_D 함포 흐름, raid 중 함포 개입 항목, 종료기 등)는 달라질 수 있다.
  - 항목별로 차이와 원인을 표로 보고한다. **승인된 기대값은 임의로 갱신하지 않는다.** 갱신안은 PR에서 사용자 승인을 받는다.
- **GUN_B1에서 보류된 CG 도메인 기대값 3건**(탄약 질량 노드 분할로 인한 IEEE-754 합산 차이, cg.x ~8.88e-16 m): **사용자 승인됨, 이번에 갱신한다.** 갱신 전후 값을 기록한다. EW 원시 저장 비교 2건(Mod4 ID / HE-MFF 배분 경로)도 같은 성격이면 함께 갱신하고 경로를 기록한다.
- 저장 스키마 변경 0. 진단 플래그는 저장하지 않는다.
