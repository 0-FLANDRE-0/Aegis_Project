# 안정화 실행 순서

1. 기존 B SHA 및 보호 브랜치/원시 증거 고정. 기존 비용 Δ1 HOLD와 >12 HOLD 재현.
2. 후보 설계: native NIS winner/gates 유지, 실제 native S의 log determinant가 같은 선택을 뒷받침할 때에만 HOLD 해제. 근거 누락/충돌/실제 동률은 HOLD 유지. 측정 차원과 epoch 불일치에 새 근거 사용 금지.
3. >12 성분: native 전역 해를 한 번 계산하고, real+dummy row-minimum lower bound로 근접 대안에 필수인 edge만 인정. 미증명 edge는 HOLD. 작은 성분의 기존 정확 대안 검사 유지.
4. 후보 SHADOW와 기존 B의 실제 상태/결과 동일성을 확인하고 native 음성·양성/포화/순열·독립성 검증 후 ACTIVE 생성. 기존 기대값 갱신 없음.
5. A / 기존 B SHADOW / 기존 B ACTIVE / 새 후보 SHADOW / ACTIVE 자연 탐지→AUTO→발사→종말 전투. 기존 paired4+D1419012 strict를 별도 유지하고 결과·품질 근거와 함께 분류.
6. 원래 도메인/UI/WebGL/자연 관측/IFF/idle 회귀, 독점 성능 관측, diff·체크섬·다운로드 ZIP·원격 readback. 미승인 차이와 범위 미구현을 숨기지 않고 최종 완료 가능 여부 보고.

새 계수로 승률을 맞추거나 검사를 완화하지 않는다. 새로운 측정 증거는 물리가 아니라 연관 판단에만 사용한다.
