## Owner separation conclusion

- The active-player WIP118/WIP119 path uses global compatibility aliases, but those aliases are pinned to `ACTIVE_SHIP_RUNTIME`; it is not invoked as a foreign-owner controller.
- Foreign DDG/CG defense uses the same decision source inside `createOwnerWeaponExecutionD` with lexical owner-local `tracks`, `missiles`, `ciws`, inventory, damage, and RNG roots.
- Network reports and leases carry measurements/covariances and local file ids. They do not grant remote FCS; the browser oracle records `NETWORK_ASSIGNED_PEER` at the assigned-away owner and `LOCAL_FCS_REQUIRED` at the peer without a local fire-control file.
- Truth access remains in sensor-front-end construction, diagnostic fixtures, physical flight/collision, and damage resolution. No audited upper-decision function consumes a physical target object.
- No unresolved active/foreign mutable-root leak was found. Commit C may proceed with an owner-addressed immutable adapter; any fallback from an explicit owner to `ACTIVE_SHIP_RUNTIME` remains prohibited.
