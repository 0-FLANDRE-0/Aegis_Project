# 검증 환경과 해석

- Managed Linux 컨테이너, CPU quota 4 cores. Node 24.19.0 / Python 3.12.14 / Chromium 151.0.7922.173.
- 게임 HTML 전체를 `https://aegis.test/`로 Playwright route에 공급한다. 출항 UI를 통과한 뒤 고정 seed로 일시정지하고 네이티브 1/60초 업데이트를 호출한다. 별도 근사 비행 모델을 실행한 결과를 실제 게임 요격으로 부르지 않는다.
- 시험용 코드 삽입본의 gzip과 loader SHA 메타데이터를 함께 갱신한다. 배포 HTML에는 `live-fixture.js`를 삽입하지 않는다. 배포 코드에는 관측 기반 종료기와 명시 호출 진단만 있다.
- 2D Canvas는 기존 검증용 `--disable-accelerated-2d-canvas`를 사용한다. WebGL은 소프트웨어 SwiftShader다. 물리 폰/GPU FPS 인증은 수행하지 않는다. UI 회귀는 1400×900 / 832×384 / 384×832, DPR 2.8125를 포함한다.
- 주 비행 비교: 미사일별 고도 30/5000/15000m × 중·장거리 2개 × seed 5개 × 종료기 OFF/ON = 240발. 중·장거리는 SM2 60/140, ER 100/220, SM6 100/240, ESSM 12/35km다. 표적은 접근 250m/s의 직선 등속 시험 항공기다. 함의 레이더 트랙은 명시적 시험 정보로 공급하지만 RF 프런트엔드와 시커 EKF는 실제 게임 것을 쓴다. 전체 전술 AI나 모든 바다/전자전 환경에 대한 일반 승률은 아니다.
- 원래 PIP_B 같은 120조건도 별도 실행했다. 신관/유도/힘 모델이 달라지지 않았다는 정적 증거와 사격 결과 변화를 구분한다. Dynamic B4가 바뀌면 모든 비행 결과가 이전 버전과 같을 수는 없다.
- 실제 RF 경로의 ON/OFF 비교에서 두 ESSM 첫 실행의 비행 시간 차이 최대 0.283333s, 신관 거리 차이 최대 0.421571m를 관찰했다. 같은 종료기 OFF끼리의 반복에서도 첫 실행과 이후 실행에 0.283333s 차이가 재현됐다. 비트 단위 전체 RF 궤적 동일성을 주장하지 않는다. 명중/신관 경로 보존과 조기 종료 0건을 판정한다. 반면 분리된 이상 유도 ENV 진단과 같은 네이티브 게임 경로의 궤적은 5,894샘플에서 모든 비교 성분 오차 0이다.
- 배터리는 실제 비행 후 시험 시계를 수명 경계로 옮겼다. SM-6는 449.95초 체크포인트 뒤 450~480초 구간의 네이티브 비행을 진행한다. 전원 조건 검증이며 자연 비행 480초 완주나 사거리 인증이 아니다.
- 최초 도메인 회귀의 헬기 1 suite는 sparse checkout에 옛 CG_A 기준 파일이 없어 실행 전에 중단됐다. 기준 파일을 동일 Git blob으로 체크아웃한 뒤 같은 검사 85건이 통과했다. 실패 시도 로그와 성공 영수증을 모두 보존한다. 제품 코드 수정으로 테스트를 피하지 않는다.
- 각 원시 영수증에는 실제 시험한 HTML SHA를 남긴다. 최종 사거리 표를 넣은 재패킹 후에는 loader/소스 대조, 네이티브 해시, 표 해시/변경 경고, 사거리 경계, 최종 브라우저 스모크를 다시 확인한다. 이전 시험 영수증의 SHA를 최종 SHA로 바꾸지 않는다.
- GitHub Actions는 사용하지 않는다. 수동 workflow만 준비하고 dispatch, main/이전 브랜치 병합, 새 PR은 하지 않는다.
