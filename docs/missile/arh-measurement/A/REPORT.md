# ARH_MEASUREMENT_CONTRACT_A — 현재 SM-6 설정 확인

**현재 활성 SM-6 설정에서도 두 종류의 불일치가 모두 재현된다.** 첨부 기본값을 실제 설정인 것처럼 재사용하지 않았다. 제품 코드·계수 변경0, 새 비행 적분0이며 수정이나240km 명중 회복 시험은 하지 않았다.

## 실제 설정과 실행 경로

기준은 `sm6-240km-rf-diag-a@aa7298be839a4a67dc817cd62b46d7d8f77fcf6f`, 제품은 `launch-handoff-a@99c2ef33`의 HANDOFF SHA `e42a2e05b8ff2096dfb334e7b9427cd2cd6da46d567083f06620ffdf35729ed7`다. DZT SHA `edc159fa347d721d61d80228e2512665f22da0adb4f02fdf4e2dbe82789e0c9c`도 대조했다. 별도 진단 브랜치 `arh-measurement-contract-a`에 자료만 추가한다.

기존 정식 VLS 경로가 만든 실제 미사일 객체(`isSM6=true`, `SM6_BLKIA_SIM`, guidanceCore v1)에서 `getSamArhProfile(m)`을 읽었다. fixture의 `maxTimeS=0`으로 life0/tick0을 확인했다. 이는 설정을 읽기 위한 객체 생성이며 새 비행/명중 시험이 아니다.

활성 모드는 **RF_V2**, 프로파일은 **SM6_BLKIA_ARH_RF_V2_WORKING**이다. DZT와 HANDOFF의 전체 프로파일이 같은 SHA `38339c16858d23f49bdb79866e0f4fbc1f815c901c05584936f23923b3388f83`였다.

## 1. 점의 절대각이 시커 방향에 끌리는 불일치

단일 합성점, 거리26km, power1/SNR20, TRACK, 탐지 draw0·각도 잡음 draw0 조건이다. 활성 프로파일 값을 바꾸지 않았다. 방위와 고각을 각각 검사했고 같은 현상이 나왔다.

| 실제 점의 방위 | 시커 중심 | 현재 SM-6 반환 절대 방위 |
|---:|---:|---:|
| +0.5° | 0° | **+0.064163527°** |
| 0° | +0.5° | **+0.435836473°** |
| 0° | -0.5° | **−0.435836473°** |

고정된 점의 실제 방향이0°인데 시커 방향을 바꾸면 반환 절대각이 약±0.43584°로 움직인다. 잡음 없는 점의 절대 기하각을 반환한다는 계약은 현재 설정에서도 실패한다. 이 구간은 기존 angle gate에 걸리는 큰 각도 특례가 아니다. ACQUIRE/REACQUIRE의 점 확인도 같은 결과다.

상위 `_arhMonopulseMeasurement`의 RF_V2 dispatch 결과와 직접 생성 함수 결과가 일치했다. `_arhDecorateMeasurementFromCluster`는 각도와 sigma를 그대로 유지했다. 이 합성 clean point는 TRACK_ECHO로 분류되며 뒤에서 편향이 상쇄되지 않았다.

실제 `_sarhMeasurementModel`은 표적/수신점의 위치로 절대 방위·고각을 계산하며 시커 중심에 끌리는 이 생성식을 관측 예측에 포함하지 않는다. 따라서 생성기의 의도적인 편향 모델로 해석하더라도 현재 기하 관측 모델과의 의미 차이가 남는다. EKF 행렬 연산 오류를 증명한 것은 아니다.

## 2. 생성 각도 잡음과 반환 sigma/R의 불일치

같은 정면 합성점을 후보별20,000회 관측했다. 총40,000회 **분리된 측정 함수 호출**이며 미사일40,000발이 아니다. 독립적인 결정적 표준정규 스트림(seed `0x71c42a19`)으로 각도·거리·Doppler 잡음을 공급했다. 게임 전체 RNG나 항법/센서 RNG 스트림을 바꾸거나 소비하지 않았다.

| 축 | 생성 σ(°) | 표본 σ(°) | 반환 σ(°) | 실제 R의 √분산을 각도로 환산(°) | 생성/R σ 비율 |
|---|---:|---:|---:|---:|---:|
| 방위 | **0.093057085** | 0.093174763 | **0.016546903** | **0.016546903** | **5.62384배** |
| 고각 | **0.093057085** | 0.092382741 | **0.021000000** | **0.021000000** | **4.43129배** |

생성 σ는 draw+1/−1의 출력 차이와 실제 생성식에서 얻었다. 표본은 독립 스트림의 통계 확인이다. 현재 점 조건에서 생성식의 표준편차는 `0.074/√(0.35+12) + 0.16×0.45 = 0.093057085°`다. 반환 방위 sigma는 `max(0.015,0.074/√20)`이고, 고각은 해당 계산이 하한0.021°에 걸린다.

decorate 후 `_arhMeasurementCov`의 R[5]/R[10]을 직접 계산해도 생성 잡음까지 커지지 않았다. 이 clean point의 ECCM 공분산 배율은1이다. 분산 비율로는 약31.6275배/19.6363배다. 이는 **이 합성점/신호 조건의 결과**이며 실제 비행 모든 거리·SNR에서 고정된 보정 배율이라는 뜻이 아니다. 이 숫자를 곱하는 제품 수정은 하지 않았다.

## 실제 함수 동등성과 검사 판정

실제 브라우저에서 동일 입력22개를 `_arhMonopulseMeasurement → decorate → R`로 실행하고, 현재 함수/현재 프로파일을 넣은 독립 VM 결과와 비교했다. **최대 차이0**이었다. 브라우저의 기존 난수 함수는 finally에서 복원했고, 전/후 게임 RNG·프로파일·물리 tick/life는 그대로였다. 수학 상수TAU도 실제 값과 일치했다.

현재 설정 시험의 종료코드1은 측정 계약 위반3개를 검출한 예상 결과다. 실패를 PASS로 바꾼 검사가 아니다. 별도의 `verification.json.diagnosticPass`는 재현 절차와 출처 확인이 성공했다는 뜻이며 **측정 계약이 정상이라는 뜻이 아니다**.

최초 VM 실행은 TAU 바인딩 누락으로 중단돼 폐기했다. 분리시험 환경에 실제 수학 상수2π를 바인딩한 뒤 재실행했고 native22점과 오차0을 확인했다. 이 도구 수정은 제품이나 측정식을 변경하지 않는다. 무효 실행 로그를 따로 보존했다.

## 이번 단계의 범위

현재 활성 설정과 실제 dispatch/decorate/R까지 두 불일치가 남는다는 확인을 마쳤다. 이전 실제 비행의 EKF 갱신 오차 증가와 연결되는 구체적인 조사 대상이지만, **이를 수정했을 때 원래240km 실패가 해소되는지, 다른 정상 시드가 보존되는지는 이번에 시험하지 않았다.** 실제 장면의 연관·가림·상태 공분산·다른 유도원 기여도까지 모두 배제하지 않았다.

PN/Kappa, 승격 gate, 추진/공력/G, 신관/Pk, 프로파일·계수와 저장 스키마를 바꾸지 않았다. 새 HTML·사거리 재측정·전체 회귀·main/원본 브랜치 병합·release/tag 생성도 없다. 원래 제품과 이전 진단 자료는 보존한다.
