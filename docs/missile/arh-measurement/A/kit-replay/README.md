# AEGIS ARH 측정 계약 추가 조사 A

2026-10-25. 제품 변경 0, 이 환경에서 새 비행 실행 0.

이번 조사에서는 저장된 실제 실행 로그를 재계산하고, 선택된 제품 HTML에서 추출된 측정 함수를 별도로 실행했다. **기존 비행의 오차가 측정 갱신 안에서 만들어지는 점을 확인했고, 측정 함수의 기본 각도 설정에서 재현되는 계약 불일치 두 종류를 찾았다.** 현재 활성 SM-6 프로파일로 그 불일치를 다시 확인하거나, 이를 바로잡아 원래 240km 실패가 해소되는지 비행 시험한 상태는 아니다. 근본 원인 규명 완료나 수정 완료로 읽으면 안 된다.

기준은 `sm6-240km-rf-diag-a@aa7298be839a4a67dc817cd62b46d7d8f77fcf6f`이다. 원래 제품은 `launch-handoff-a@99c2ef33e5256acbfb3aa557a01065669404de89`, HANDOFF HTML SHA-256은 `e42a2e05b8ff2096dfb334e7b9427cd2cd6da46d567083f06620ffdf35729ed7`이다. 원래 AIR/Su-35, 240km/5km, 접근250m/s, seed12001, 종료기OFF 조건을 해석했다. 입력·게임·계수를 바꾸지 않았다.

**저장된 실제 실행에서 확인한 것**

| 시각 | EKF 갱신 전 속도 오차 | 갱신 후 속도 오차 | 갱신 후 추정 측방 속도 |
|---:|---:|---:|---:|
| 147.850s | 0.478821m/s | 17.984535m/s | 12.973518m/s |
| 147.950s | 35.332278m/s | 85.821989m/s | 85.686610m/s |
| 148.500s | 287.960555m/s | 293.851034m/s | 293.657143m/s |

물리 표적의 측방 속도는 약0이다. 표적이 실제로 옆으로 달린 결과가 아니라 필터가 그런 운동을 추정한 것이다. 표의 세 시점은 모두 fresh EKF 갱신이며 accepted=true다. 전체 속도 오차와 측방 성분은 서로 다른 값이므로 구분했다.

147.950s에서 raw ARH 속도 오차와 실제 소비한 상대 속도 오차는 둘 다85.82198942523894m/s였다. 이 시점의 초기 확대를 전달 어댑터의 별도 좌표 변환 오류로 설명할 근거는 없다. 비행 전체의 모든 어댑터 동작을 검증했다는 뜻은 아니다.

147.8166667s 초기 측정의 거리/방위/고각을 같은 PRE_DYNAMICS 물리 수신점에서 직교좌표로 바꾸면 실제 로그의 EKF 초기 위치와 차이가8.731149e-11m다. 즉 이 초기화 경로는 측정각을 절대 기하각으로 직접 해석했다. 직선 표적의 운동은 저장된 실제 truth 한 점에 고정했고, 거리·고도·측방 좌표는 같은 로그 행을 썼다. 후속 틱의 위치를 섞지 않았다.

ARH 값만 이상화한 기존 실행에서도148.500s의 **원래 RF/EKF 내부** 속도 오차는289.258148m/s였다. 반면 유도기가 소비한 오차는0이고, 미사일 측방 좌표는0.595161m였다. 과도한 실제 측방 기동이 없어도 초기 필터 오차 확대는 남는다. 두 실행은 개입 후 궤적과 관측열이 달라지므로 같은 잡음열의 대조군으로 취급하지 않았다.

위 계산은 기존 CSV를 검산한 것이다. 이곳에서 NATIVE를 재실행한 결과가 아니다.

**분리시험 1: 점의 각도가 시커 방향에 끌린다**

선택 HTML에서 추출된 `_arhV2MonopulseMeasurement` 본문을 그대로 실행했다. 함수 SHA-256은 `9b206aa5727f5bffc11513f0bea56e0d82615352689454b0c3144fd57368579a`이며 DZT/HANDOFF 캡처에서 본문이 같다.

단일 점, 잡음0, 검출 성공을 고정했다. 각도 파라미터는 캡처 함수의 기본값을 사용했고, 오차 필드는 합성 프로파일을 사용했다. **현재 활성 SM-6 프로파일을 복원한 시험이 아니다.**

| 실제 입력 방위 | 시커 중심 방위 | 반환된 절대 방위 |
|---:|---:|---:|
| +0.500000° | 0° | +0.065418° |
| 0° | +0.500000° | +0.434582° |
| 0° | -0.500000° | -0.434582° |

고정된 점을 관측하는데 시커 방향만 바꾸면 반환된 절대각도 바뀐다. 절대 방위를 반환하는 무편향 점 관측이라는 계약에서는 실패다. 이 편향이 의도된 센서 모델이라면 필터의 관측 모델도 이를 표현해야 한다. 현재 로그의 초기화는 반환 각도를 직접 기하각으로 사용했다.

이 현상은 시커의 움직임/측정 잡음이 가짜 표적 운동으로 해석될 수 있는 구체적인 경로다. 다만 실제 활성 프로파일, 상위 dispatch와 측정 decorate 단계의 보정 여부까지 확인하지 않았으므로 이것만으로 원래 SM-6 비행의 단독 원인이라고 단정하지 않는다.

**분리시험 2: 생성 잡음과 반환 오차 크기가 맞지 않는다**

같은 함수의 기본 각도 설정과 합성 오차 필드에서, 정면의 고정 점을20,000번 관측했다. 이는 분리된 함수 호출20,000회이며 비행20,000발이 아니다. 진단 전용 결정적 난수 스트림을 사용했고 게임 RNG에는 접근하지 않았다.

| 합성 입력 설정 | 생성 각도 잡음 표준편차 | 표본 표준편차 | 반환 azSigmaDeg |
|---|---:|---:|---:|
| 함수 기본 각도 잡음/글린트 | 0.100456° | 0.100583° | 0.020000° |
| 글린트 입력만0.32°로 변경 | 0.172456° | 0.172674° | 0.020000° |

첫 행에서 생성 표준편차는 반환값의 약5.02배다. 두 번째 행은 잡음을 바꿔도 반환 오차 필드가 함께 바뀌지 않는다는 반례다. 생성식의 각도 잡음/글린트 파라미터가 반환 sigma 식에 반영되지 않는 구조를 확인할 수 있다. **이 수치를 현재 SM-6의 실제 잡음 크기나 보정 배율로 사용하면 안 된다.**

실제 NATIVE 로그의 초기 반환 sigma는 방위 약0.017°/고각 약0.021°다. 활성 프로파일과 실제 측정 공분산 함수를 추가로 확인해야 이 값이 생성 잡음을 얼마나 설명하는지 판정할 수 있다. 이번 결과로 임의 배율을 곱하는 수정은 제안하지 않는다.

**재현과 검사 결과**

압축을 푼 폴더에서 다음을 실행한다.

```sh
node run_contract_checks.cjs
python3 verify_saved_evidence.py
```

첫 명령은 캡처한 기준 함수의 계약 위반4개를 검출해 **종료 코드1**을 반환한다. 기존 동작을 정답으로 놓은 PASS 검사가 아니다. 결과는 `contract_results.json`에 저장된다. 두 번째 명령은 출처 해시와 저장된 비행 증거의 산술을 검산하며 PASS/종료 코드0이었다. 결과는 `evidence_results.json`이다.

- 실제 제품에서 추출된 함수 해시: 일치.
- 가져온 원본 압축 CSV2개의 Git blob: 저장소 트리와 일치. 원본 SHA-256/크기는 `provenance.json`에 기록.
- 단위시험의 기하 계약2개/오차 메타데이터 계약2개: 기준 함수에서 FAIL 재현.
- 저장된 NATIVE/이상화 로그의 산술: PASS.
- 실제 브라우저 비행 재실행, 현재 활성 SM-6 프로파일 시험, 제품 수정, 전체 회귀: 미실행.

**현재 결론과 정확한 다음 진입점**

가장 구체적인 조사 대상은 측정 생성과 필터 해석 사이의 각도·불확실성 계약이다. 측정 갱신에서 가짜 측방 속도가 커지는 실제 증거와, 분리된 생성 함수의 계약 실패가 연결 후보를 만든다. EKF 행렬 연산 자체의 오류를 증명한 것은 아니다. 연관 오류, 초기화/관측성, 공분산 처리 등 다른 기여도 아직 전부 배제하지 않았다.

다음 작업에는 현재 선택 HTML의 활성 SM-6 프로파일과 다음 함수 본문이 필요하다. 기존 `provenance.py`의 추출 목록을 확장하면 전체 비행을 다시 돌리기 전에 확인할 수 있다.

- 활성 `getSamArhProfile` 반환값과 `_arhMonopulseMeasurement` dispatch.
- `_arhDecorateMeasurementFromCluster`, `_arhMeasurementCov`.
- `_arhServoCue`, `_arhInnovationStats`, `_sarhMeasurementModel`, `_sarhMeasurementJacobian`.
- 필요하면 최초 갱신 구간의 실제 seekerAngle/seekerEl, 각도 생성 전후 값과 실제 R.

현재 프로파일에서도 위 점 관측 계약이 실패하는지부터 확인한다. 생성 값과 이를 소비하는 관측 모델의 의미를 맞춘 최소 변경을 검증한 뒤에 원래 AIR/native RF 한 조건과 기존 정상 시드들을 비교해야 한다. PN/Kappa 이득이나 새 승격 gate로 이번 불일치를 덮는 방식은 이 조사의 결론이 아니다. main/제품/계수는 이번 조사에서 변경하지 않았다.

저장소의 큰 실행 HTML과 전체 압축 raw를 이 환경으로 가져오는 경로가 제한됐고 로컬 Chromium 실행 파일도 없어서, 현재 자료로 가능한 독립 검증은 여기까지다. 과거 HTML에서 찾은 추가 helper를 현재 코드인 것처럼 섞어 실행하지 않았다.
