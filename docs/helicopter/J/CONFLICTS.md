# HELI_CG_B — 원형 복원과 사용자 교정

기준 HELI_CG_A `3ce88eb81395d05c5374ea45f2bfa20418d0eaed`. 이 단계는 이전 구현의 실제 형상 판단 오류를 수정한다.

1. 사용자는 후방 좌현에 있는 옆으로 열리는 문과 내부 두 기의 나란한 격납을 지적했다. A의 후벽 전체 폭 개구·상부 접힘 문은 폐기한다. A의206개 검사는 잘못 정한 형상 안에서의 내부 일관성을 검사했으며, 실제 함선 형상의 정확성을 증명하지 못했다.
2. 원본 CG 자산의 좌현 문은 구조 mesh의 독립된12삼각형 부품이다. 원본 좌표는 x≈−30.664~−30.413m, 측방−6.580~−2.180m, 높이9.800~14.900m. 이 형상과 원본 해치·창의 세부 정점을 새 큰 판으로 대체하지 않는다. 분리된 전체 문/해치/창은1456삼각형이다. 치수는 원본 모델 등록값이며 실제 조선소 수치가 아니므로 SIM_TUNED다.
3. [벙커힐 후방 현장 사진, Theresa O’Connor, 2004년 업로드](https://www.flickr.com/photos/hober/1875702/in/album-48603)는 좌현 개구·우현 세로 패널·상부 창/플랫폼의 대조 근거다. [US Navy/DVIDS 벙커힐 MH-60R 정비 사진, 2022년](https://www.dvidshub.net/image/7568297/bunker-hill-helicopter-maintenance)과 [2022년 헬기 운용 사진](https://www.dvidshub.net/image/7548497/bunker-hill-helicopter-operations)은 내부 공간/접힌 기체/갑판 연결을 확인하는 보조 근거다. 내부에서 밖을 본 사진만으로 후벽 전체를 개방부라고 추정하지 않는다. 정적 사진만으로 구동 기구를 실증했다고 주장하지 않으며, 문 이동은 사용자 지시에 맞춘 측방 슬라이드·SIM_TUNED 이동량이다.
4. 두 기는 같은 선수·선미 위치에서 평행하게 주기한다. 좁은 좌현 출구를 막은 H1을 H2가 관통할 수 없으므로 A의 임의 선출격 순서는 유지하지 않는다. 사용자에게 구현 전 이 충돌을 보고했다. H2만 명령하면 출격 대기로 남고 사유를 표시하며, H1을 자동으로 무단 출격시키지 않는다. H1 명령이 오면 먼저 처리하고 실제 갑판을 비운 뒤 H2를 같은 출구로 이동한다. 이 변경은 CG 시설에만 적용한다.
5. 10+20+30+45+10+5=120초, 한 패드, SI/fixed60Hz, 렌더 읽기 전용, 비행·로터·센서·Hawklink·IFF·F1 OTH 정책은 유지한다. DDG 독립된 두 문과 출격 경로는 보존한다.
6. 수정 전 CG I1의 지상 이동을 그대로 계속하면 복원한 벽을 관통한다. 엄격히 유효한 I1만 J1로 migration한다. 공중 기체의 전체 상태는 보존하고 지상에서 이미 주문한 기체만 원래 주기 위치의 대기열로 되돌린다. 나쁜 I1 값을 migration으로 덮어 허용하지 않는다. DDG E1은 같다.
