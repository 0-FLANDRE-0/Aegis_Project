# PIP_B — 표시 계층 변경

기준은 SHA-256 `76c77b5c80835f87654c8aa39cd6a82c1ad66de8bc408ebad675997157024847`의 PIP_A다. `build.py`가 고정한 기준에 검토 가능한 패치만 적용한다.

- PiP 아래 제목·캡션·보조 버튼 줄을 없애고 제목 아래를 지도에 할당한다. 기존 중심/전환 버튼 노드와 리스너를 제목 메뉴로 옮겼다. 빈 바다 상황 메뉴에도 같은 명령 경로를 연결한다.
- 락온 카드를 일반 창으로 이동한다. 기존 `lockedTrackCardLines`의 행을 그대로 사용하고 DOM만 125ms마다 갱신한다. 실제 락/관측/발사 권한은 변경하지 않는다. 지도에는 락 브래킷과 번호를 표시한다.
- INFO/LOCKED/메뉴/후보/취소 칩/제목줄을 11px·1.3 행간으로 정리한다. 일반 버튼은 28px 표시와 36px hit 영역, 정밀추적 등 기존 위험 조작은 40px 이상을 유지한다.
- 2D 빔 기본값 OFF. SYS 설정만 localStorage에 저장한다. 켜면 원래 센서 표시 블록을 실행한다. 3D 센서 표시는 그대로다.
- 기존 창 메뉴가 하단 바나 고정 교전 위젯에 가려지지 않게 같은 메뉴 노드를 팝업 계층으로 이동하고 화면 안에 제한한다. PiP의 기존 크기 조절 모서리를 캔버스 위에 유지한다.

게임 save schema·truth·센서·유도·시간 코드는 변경하지 않는다. ENV_A는 별도 독립 진단 API이며 [`docs/envelope/A`](../../envelope/A/README.md)에 경계를 기록했다.

## 검증 스크립트

- `verify_static.py`: 패킹 14개, JS 구문, 원본 함수 변경 범위, 고정 기준 재빌드, 원본 모델/저장 코드 보존.
- `verify_ui.py`: P1–P4, 세 화면×85/100/130%, 락 창 8Hz, 닫기 억제/재지정, 센서 설정.
- `verify_beams.py`: 같은 고정 view에서 PIP_A/센서 ON 그리기 명령 전수 비교.
- `verify_pip.py`, `verify_render.py`: PIP_A의 입력·좌표·후보·핀치·고배율·갱신·저장 회귀. 중심 버튼의 새 메뉴 위치만 이동 경로로 반영했다.
- `run_map.py`, `verify_ui_a1.py`: MAP_A와 UI_A1의 동작 검사를 유지한다. 이번에 명시된 제목 글자 11px만 기대값을 바꿨다.

한 화면에서 실패한 시간 민감 포인터 검사는 계산 작업과 겹친 과부하를 제거한 조건에서 같은 원본 이벤트 경로로 재실행한다. 실패 이력을 숨기거나 동작 검사를 무조건 통과시키지 않는다. 최종 보고서에는 원본 입력/최종 통합 검사와 테스트 해시를 구분한다.

## 항적 원 수정

기본 DDG 출항·3D 전환·PiP 반경0.5km에서 재현했다. 원은 센서·클러터·피해 영역이 아니라 자함 항적선이다. 원본 `lineWidth=1.5`는 world 단위였고 정지한 항적에 round cap이 겹쳤다. 기존 작은 PiP에서 두께37.8px(반경 약197m), 반경0.1km에서는189px까지 확대됐다. 해당 선만 가린 이미지 비교와 스타일/호출 경로를 보존했다. 수정은 `screenPxToWorld(1.5)`이며 새 PiP에서 40/0.5/0.1km 모두1.5px다. 시뮬 항적 데이터는 그대로다.
