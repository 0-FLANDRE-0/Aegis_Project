# 검증 환경과 후보 구분

- OS Linux x86_64, cgroup CPU4개·메모리 제한 환경. Node/Python/Chromium 버전은 실행 영수증에 기록한다.
- 고정 seed1831565813. 게임 tick1/60초. UI와 카메라는 표시 계층에 둔다.
- 좌표/입력 검사는 실제 DOM·캔버스 변환을 쓰되 CPU-only view flag fixture를 사용한다. 실제3D는 별도 SwiftShader WebGL 페이지에서 검증한다. 실제 폰 GPU 성능 측정으로 표현하지 않는다.
- 소프트웨어 GPU의 가속2D 캔버스가8–9초/프레임까지 걸린 기록이 있다. `browser_backend.py`가 검사용 브라우저의 가속2D만 끄며 실제 WebGL은 유지한다. 입력 검사를 강제 클릭으로 우회하지 않는다. 느린 실제WebGL 클릭은 안정된 두 프레임을 기다리도록 timeout만 늘린다.
- 기존 native 회귀는 `docs/map/A/verify_regressions.py`의 원래 assertion과 이미 기록된 창 이동 대응 fixture를 쓴다. 구형281px AIR 높이는 실제 창 client 높이로 대응하며, 펼쳐진 창이 지도를 가리지 않게 닫는 등 입력 위치만 이동한다.
- 일부 구성 검사는 표 내장 전 후보 `68269698…` 또는 `b7d85190…`에서 수행했다. 전체PIP_B 제품을 최종 SHA에서 테스트한 것으로 소급 표기하지 않는다. 원본 영수증 SHA, 최종 구문/함수 보존 검사와 최종 직접 UI/기하/입력/120초 해시/ENV_A 경로 비교를 함께 제공한다.
- 최종 직전/최종 차이는 항적선 world→1.5px, 원래 CIWS표시 조건 보존 등 그리기 계층이다. 원본 센서/비행/유도/로프트/신관/고정tick/저장 본문은 동일하다. 내장 ENV_A는 명시 호출 전 계산을 시작하지 않는다.
- 실제WebGL 보기 전환은 각 화면5왕복을 검사한다. 기존90프레임 성능 샘플링의 기본값은 재현 스크립트에 유지한다. 이번 부가 프레임 측정은 동시 대규모 ENV_A 계산 중12프레임×4실행으로 축약하며, 기능 assertion은 유지한다. 이 부가 측정에서 속도 향상이나 실폰 FPS를 결론 내리지 않는다.
- 판정 대기 시간이 만료된 최초 GPU/롱프레스 시도는 retries 기록으로 구분하고 최종 pass 합계에 넣지 않는다. 최종 assertion을 무조건true로 바꾸는 코드는 없다.

실행 HTML만 든ZIP과 보고서ZIP은 분리한다. 보고서ZIP의 manifest는 수록 파일의 압축 해제 bytes/SHA를 기록한다. 원격 readback은 자기 자신을 포함하는 순환 검증을 피하기 위해 발행 후 저장소의 `remote-publication.json`에 별도로 남긴다.
