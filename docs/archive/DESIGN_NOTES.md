# 설계 메모

아직 지시서가 되지 않은 생각과 코드 조사 결과를 적는다. 지시서로 옮기면 해당 항목에 표시한다.

## U3 하푼 cue — 현재 코드 (2026-11-06 조사, 제품 CUE_A-1)

- 발사 cue는 함정 EKF 트랙을 발사 순간 얼린 값이다(`harpoonMemoryA`): 위치, 속도, 6×6 공분산(`tr._kfP`). truth는 쓰지 않는다
- 중심: 위치 + 속도 × 경과 시간으로 이동한다(`harpoonPredictionA`). 즉 ASM보다 이미 앞서 있다
- 수색 범위(`cueGate`):

  ```text
  min(4000 m, max(250 m, 3·√(λmax + 75² + (0.04·t²)²)))
  ```

  - λmax = 위치 공분산을 시간 전파한 값의 최대 고유값
  - 0.04·t² 항은 상수 가속을 가정한 기동 여유(자체 계산)
- **4 km는 고정값이 아니라 상한이다.** 장거리 + 변침에서 3σ가 4 km를 넘어도 잘리는 게 B 감사 실패의 원인이다
- 경로점(route) 모드에서는 공분산과 무관하게 4 km 고정이다
- 하푼 시커: 탐지 거리 18 km, gimbal 제한, 탐색 각도 = `atan2(cueGate, 남은 거리)`

### U3에서 정할 것

- ~~4 km 상한 처리~~ → 시커 물리 범위(탐지 거리·gimbal)를 상한으로 (2026-11-06 결정)
- 경로점 모드 바구니도 공분산 기반으로 바꿀지
- 하푼 발사 cue는 이미 속도·공분산이 있다. 그래서 CUE_A-1에서 `velocity:null` 때문에 쓰이지 않던 "속도 있음" 경로가 처음으로 실제 게임에서 쓰인다

## 적 항공기 재제작 때

- 발사 cue에 위치뿐 아니라 "얼마나 자신 있는지"(공분산)와 정보 시각을 같이 넘긴다.
  - 예: RWR만으로 잡았으면 거리 σ를 크게 잡는다. 레이더 트랙이 있으면 속도·공분산을 같이 넘긴다.
  - 발사 측이 원래 아는 정보라 truth 위반이 아니다.
- 현재 구현(삭제 예정): RWR 거리 추정이 실제의 0.6~1.5배, 편대 공유 ±2 km 난수, 시각 없음. 미사일 필터는 이걸 모르고 기본 INS 오차(수백 m)로 시작한다.
- 지금 ASM 바구니는 대부분 하한 `0.12R`이 정한다. 100 km에서 하한은 12 km이고 물리 상한은 약 4 km다. 하한이 발사 오차를 대신 메우고 있는 셈이라, 발사 공분산이 생기면 하한을 다시 본다.
- cue 행렬 시험 fixture는 발사 위치를 정확하게 준다. 재제작 후에는 실제 발사 경로 오차를 넣은 시험이 필요하다.

## 방사원·EMCON (EMITTER_A / EMCON_B)

- 소비자는 **관측 가능한 값만** 읽는다: 범주, family, 대역, 세기·SNR, 각도.
- `owner`, `ship`, 플랫폼 종류, 좌표는 합성 내부 전용이다.
- 이유: 함정 재머와 눌카는 둘 다 `JAMMER`라서, 구분하려면 truth가 필요하다. 그래서 중기 수동 RF에서는 둘 다 빼고 HOJ에서만 처리하기로 했다.
- 범용화할 때도 이 계약을 지킨다.
