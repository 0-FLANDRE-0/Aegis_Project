# MAP_C 지시서: 교전 UI 정리(라벨 축소, 추종 태그, 발사 슬롯 이동, 시간 블록 이동, 탭 선택 개선)

## 0. 기준과 산출물

- 기준 브랜치: `map-b` (커밋 `06d668abf457a8dd3a98659e3b4535ee69612612`)
- 기준 파일: `Aegis_SIM_v48_WIP_MAP_B.html` (SHA-256 `6dfac8a6e846bc6476619d721d5113fdc638f309ef5ba0b568e0526010ed8c42`)
- 작업 브랜치: `map-c` (map-b에서 분기). main 병합, release, tag는 만들지 않는다.
- 산출물: `Aegis_SIM_v48_WIP_MAP_C.html`, 보고서·검증 자료는 `docs/map/C/`에 둔다. 구성은 MAP_B와 같다(HTML ZIP과 보고서 ZIP을 분리하고, 원격 readback 체크섬을 기록).
- 이번 작업은 **UI/입력 전용**이다. 비행·유도·센서·발사 관문·사거리표(`ENVELOPE_TABLE_D`)·저장 스키마는 바꾸지 않는다.

## 1. 링: 그대로 두고 텍스트만 축소

- 링의 종류, 개수, 고도 행(저고도 30m / 고고도 15,000m), 색, 선 모양, 사각지대 빗금, 표적 링 조회 방식은 **MAP_B 그대로** 둔다. 사거리표 값과 `otherRuns` 처리 규칙도 바꾸지 않는다.
- 바꾸는 것은 `__MAP_B__.draw()`의 링 라벨 글자 크기뿐이다. 현재 `11/z px`인 글자를 축소한다. 기준 크기는 9px로 하고, 832×384에서 읽을 수 있는지 캡처로 확인한다.
- 화면 밖 링의 `→ 표적 유효 …km` 라벨은 지금 지도 오른쪽 위에 찍힌다. 3장의 시간 블록과 겹치지 않도록 그 아래로 내린다. 다른 위치 규칙은 유지한다.

## 2. 교전 정보: 큰 패널 → 표적을 따라다니는 미니 태그

현재 `#mapEngagementB` 패널이 2D PiP를 거의 다 덮는다. 이 패널을 작은 태그로 바꾼다.

**내용** (기본 2줄, 글자는 링 라벨과 비슷한 크기):
- 1줄: 상태 원(●) + 표적 라벨 · 식별 (예: `● T6 · HOSTILE`)
- 2줄: 무장×발수 · 판정 · 거리 (예: `SM-6×2 · 유효 · 38km`)
- 판정이 주황이나 빨강이면 3줄에 짧은 사유를 표시한다. 기존 `model.reason`과 판정 문구를 그대로 쓴다(예: `사각지대 · 명중 확률 낮음`, `EMCON`, `트랙 소실`). 새 사유 문구를 만들지 않는다.
- 상태 원 색: 초록 = 유효, 주황 = 명중 확률 낮음(사각지대/최대 사거리 구간/최소 유효거리 안쪽), 빨강 = 발사 제한. 색 판정은 MAP_B의 `allowed`, `verdict`를 그대로 따른다.
- 태그에 작은 `✕`(표적 해제)를 둔다. 터치 영역은 의사 요소로 최소 28px 이상 확보한다. 동작은 기존 [취소]와 같다(표적만 해제하고 무장 선택은 유지).
- 발사 버튼은 태그에 넣지 않는다. 발사는 3장의 하단 바 슬롯에서 한다.

**추종: 끊기지 않을 것** (가장 중요)
- 지금 `positionPane()`은 125ms마다 갱신되는 `model.d.o`로 위치를 잡아서 8Hz로 뚝뚝 움직인다. 태그 **위치**는 매 렌더 프레임(rAF)마다 최신 관측 트랙 위치로 계산한다. 판정 계산(`refresh`)의 주기는 그대로 둔다.
- 측정 갱신 사이에는 관측 속도로 위치를 앞으로 예측해 보간한다(표시 전용). 시뮬 일시정지와 배속을 반영한다. 실제 적 truth 좌표는 쓰지 않는다. 새 관측이 들어왔을 때 예측 위치와 차이가 나면, 순간이동하지 말고 짧게(약 150ms) 수렴시킨다.
- 태그 DOM은 한 번만 만들고 위치만 옮긴다. `transform` 이동을 권장한다. 매 프레임 재생성하거나 hidden을 토글하지 않는다.
- 태그는 표적 심볼 옆에 붙인다. 화면이나 창 가장자리에 가까워지면 반대편으로 넘기거나 안쪽에 붙인다. 이때 좌우 전환에 여유 범위를 두어, 경계에서 좌우로 떨리지 않게 한다.
- 메인 화면과 PiP 모두 같은 태그 규칙을 쓴다. 태그는 표적을 고른 화면 안에만 표시하고, 그 화면 영역 밖으로 나가지 않게 한다.
- 트랙을 잃으면 태그는 마지막 위치에 회색으로 남기고 `트랙 소실`을 표시한다(MAP_B 판정과 동일).
- 이전 버전에서 락온 표적 옆에 떠서 따라다니던 정보 라벨이 있으면, 그 구현을 찾아 재사용할 수 있는지 구현 전 보고에 적는다.

## 3. 하단 바와 시간 블록 재배치

**시간 블록 → 화면 오른쪽 위로 이동**
- 기존 `.ui-clock-a` 노드(시계 `#uiClockA`, 일시정지 `#uiPauseA`, 배속 `.time-btn` 1×/4×/8×/16×/64×)를 **새로 만들지 말고 노드 그대로 옮긴다.** 기존 리스너와 id를 보존한다.
- 배치: 1줄은 `시계  Ⅱ`, 2줄은 배속 버튼 5개. 지도/3D 영역의 오른쪽 위에 둔다.
- 창(PiP 포함)을 위로 끌어 올려도 시간 블록이 가려지지 않아야 한다. 창 배치 범위에서 이 영역을 빼거나, 시간 블록을 창보다 위 레이어에 둔다. 구현 전 보고에 방법을 적는다.
- 3D 오른쪽 위의 `아군함 보기` 버튼과 `3D VIEW · HDG` 정보 박스는 겹치지 않게 아래로 내리는 정도만 한다. 이 둘은 나중에 정리할 예정이니 다른 변경은 하지 않는다.

**발사 슬롯 → 옛 배속 자리**
- 하단 바 순서는 `[함 정보] [무장 재고] [발사 슬롯] ··· [EMCON] [MAN] [▤] [+]`로 한다.
- 발사 슬롯은 옛 배속 자리의 **왼쪽 편**에 둔다. EMCON 칩(`#uiEmconChipA`)과는 최소 12px 떨어뜨려 잘못 누르지 않게 한다.
- 슬롯 폭은 **항상 확보한다.** 무장이나 표적을 고르지 않았을 때도 회색 슬롯으로 남겨서, 상태가 바뀌어도 바의 다른 요소 위치가 1px도 움직이지 않게 한다.
- 표시: `●  발사 ×N`
  - 원(●): 2장과 같은 초록/주황/빨강. 선택이 없으면 원을 꺼둔다.
  - 버튼: 발사 가능(`model.allowed && !queue`)이면 빨강, 불가면 회색 비활성. 비활성 사유는 태그 3줄에 나온다.
  - 연속 발사 중에는 `발사 중 2/4`처럼 표시한다.
- 버튼 id는 `#mapFireB`를 유지한다. 클릭 동작은 MAP_B의 FIRE 경로(운용자 명령 큐 → fixed tick → 정식 VLS)를 **그대로** 쓴다.
- 눈에 보이는 높이는 바에 맞춘다. 터치 영역은 의사 요소로 세로 40px 이상, 폭 72px 이상을 확보한다.

## 4. 탭 선택 개선 (메인·PiP 공통)

현재 `__MAP_A__`의 `hits()`는 탭 반경 20px 안의 객체를 모두 후보로 잡고, 2개 이상이면 `choose()`가 "겹친 객체 선택" 메뉴를 띄운다. PiP에서는 자함, 발사한 미사일, 아군함이 거의 항상 겹쳐서 매번 메뉴가 뜬다.

변경 내용 (**탭 경로만**):
1. 탭하면 메뉴 없이 **손가락 위치에서 가장 가까운 후보를 바로 선택**한다.
2. 가장 가까운 후보와 거리 차가 작은 후보들(기준 6px, 구현 전 보고에서 확정)은 우선순위로 정한다.
   - 무장을 선택한 상태면 적/미상/의심 트랙을 우선한다.
   - 자함이 발사한 미사일은 항상 마지막 순위로 둔다.
   - 그 외에는 거리순으로 정한다.
3. **같은 자리 재탭 순환**: 직전 탭과 같은 위치(약 12px 이내)를 짧은 시간(약 1.5초) 안에 다시 탭하고 후보 집합이 같으면, 다음 후보로 넘어간다. 화면에 `2/3 · T5`처럼 작게 표시한다.
4. **롱프레스와 우클릭은 기존 그대로** 둔다. 겹친 목록, `확대`, 상황 메뉴를 포함한다. 겹친 목록은 이 경로로만 연다.
5. 선택 이후 규칙은 바꾸지 않는다. 아군함은 탭하면 정보만 보이고 [통제]를 눌러야 통제된다. 통제 중 빈 바다를 탭하면 즉시 항로점이 된다. 무장 계획 중에는 통제를 전환할 수 없다. 표적을 탭하면 MAP_B의 교전 전환이 일어나고, 명시적 [정밀추적] 경로도 그대로다.

구현 전 보고에 적을 것: 객체 레코드의 어떤 필드(kind, identity, 자함 발사 여부 등)로 우선순위를 판정하는지, 기준값(6px / 12px / 1.5s)을 그대로 쓸지.

## 5. 보존 조건 (MAP_B와 동일한 수준)

- 표적 truth, entity, 적 배열, RF 물리 객체를 새 UI에서 읽지 않는다. 태그 예측 보간도 관측 트랙만 사용한다.
- 발사는 `#mapFireB` → 기존 큐 → `wip13cSelectVlsWeapon` / `wip13cFireSelectedVlsWeapon` → 정식 VLS 경로만 쓴다. 렌더 함수에서 발사하거나 시뮬 상태를 쓰지 않는다.
- `ENVELOPE_TABLE_D` 120행 byte 동일, `__ENV_D__.status()` `match:true`.
- 비행 관련 내장 지문 281개 변경 0. 기존 최상위 함수·상수는 바뀐 UI 함수만 예외로 하고, 그 목록을 보고한다.
- 120초 무표적·전투 truth 해시가 MAP_B와 같아야 한다(`fb1fac63…`, `b7d28c54…`).
- 저장 스키마 변경 없음. UI 선택/태그/순환 상태는 저장하지 않는다.

## 6. 검수

**기존 회귀**: 도메인 420, UI 88, MAP_B 91, 경고 23, 추가 13, network-only, 종료기 300발(결과 차이 0), 자연 관측 WebGL 8발, world120. 위치가 바뀐 요소를 찾던 검사는 준비 경로만 이관하고, 검사 항목은 삭제하지 않는다(MAP_B의 이관 원칙과 동일). M9는 "태그 + 하단 발사 슬롯" 구조에 맞게 고친다.

**신규** (1400×900, 832×384 각각, 2D 주화면과 3D 주화면+PiP 각각):

| 항목 | 기준 |
|---|---|
| C1 링 라벨 | 링 값·개수·색 MAP_B와 동일, 라벨 글자만 축소, 화면 밖 라벨이 시간 블록과 겹침 0 |
| C2 태그 추종 | 1×/8×/64×에서 10초 동안 태그 기준점과 표적 심볼 간 거리 편차 ≤ 3px, 프레임 간 순간 점프 0, 태그 노드 재생성 0, 표적이 유효한 동안 깜빡임(hidden) 0, 가장자리 좌우 전환 떨림 0 |
| C3 태그 내용 | 판정 6종에서 원 색과 사유 줄이 MAP_B 판정과 일치, `✕`가 표적만 해제 |
| C4 발사 슬롯 | 바 넘침·겹침 0, 터치 영역 ≥40px, EMCON과 간격 ≥12px, 선택 유무와 판정 변화 전후로 다른 바 요소의 박스 좌표 동일, 경고 3종 발사 6/6 재확인 |
| C5 시간 블록 | 일시정지·배속 5종 동작이 이전과 동일(같은 노드·리스너), 창을 끌어 올려도 가려짐 0, 3D 오른쪽 위 요소와 겹침 0 |
| C6 탭 선택 | 자함+자함 미사일+적 트랙이 겹친 PiP에서 탭 한 번에 메뉴 없이 선택, 무장 선택 시 적 트랙 우선, 자함 미사일은 마지막, 재탭 순환과 `n/m` 표시, 롱프레스 겹친 목록·확대 유지, 아군함 통제 규칙과 빈 바다 항로점 불변 |

스크린샷: 위 조건별 PC/폰 캡처를 남기고, 실제 WebGL 3D 주화면+PiP 캡처를 1장 이상 포함한다.
